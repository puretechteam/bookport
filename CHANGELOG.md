# Changelog

Newest first. Work in progress collects under Unreleased until the next release.

## 2026-11-12: bookport 0.4.0, PostScript and EPS, PDF join, split and compress, and a hardening pass

- **PDFs locked by permissions can be edited, joined, split and compressed** (`bookport.pdf.rewrite`): a PDF that opens with no password but may not be edited used to be refused outright. Now the result is locked again, with an empty user password, a random owner password nobody is told, the same /P permission bits (the fewest of them when several are joined) and AES-256 (revision 6), written from ISO 32000-2. A 3-page AES-256 file splits into 3 locked files and joins to 6 pages with /P unchanged; PyMuPDF and pdfium open and draw the results. PDFs that need a real password are still refused.
- **Typst: `#set` and `#show` lines are dropped when reading** instead of showing as code blocks (bookport's own `#set document(...)` line came back as one after a round trip: 1 stray code block, now 0). `#set document(title:, author:)` becomes the book's title and authors.
- **New: PostScript and EPS to PDF** (`bookport.ps.to_pdf`), without Ghostscript: bookport's own PostScript Level 3 interpreter, written from Adobe's reference. Paths, clips, colour spaces, pictures through every standard filter (JPEGs placed as they are), shadings, patterns, forms and fonts: Type 1 and CFF fonts embedded, TrueType (Type 42) as TrueType, Type 3 as Type 3, and the standard fonts by name with Adobe's metrics, so text is searchable. An EPS page is its bounding box; DOS EPS files with a preview and printer jobs with a PJL header are read too. Against Ghostscript on 25 files (matplotlib plots with both kinds of font, LibreOffice and Pillow EPS, Ghostscript's own ps2write output, a 60-page document), drawn by the same renderer: every page scores an SSIM of 0.99 or more, and 9 of the files, the 60 pages among them, come out pixel for pixel the same. Most files take a few hundredths of a second; the 60 pages through ps2write's PDF-reading prolog take 0.74 s (Ghostscript 0.28 s). 540 damaged programs in the tests only ever give a BookportError; programs can't touch files and are stopped if they run too long.
- **New: PDF to PostScript and EPS** (`bookport.ps.from_pdf`): Level 3 PostScript, every page or one page as EPS, cropped and turned as it shows. Fonts go in embedded: Type 1 as they are, TrueType as Type 42, CFF and OpenType CFF turned into Type 1, Type 3 as Type 3. Text is shown with the PDF's own widths: after PostScript and back, all 46,089 letters of a 41-page book land within 0.011 pt of where they were, and the text still reads back. Shadings, patterns, forms, masks, optional content and annotations are kept. Against Ghostscript's ps2write on the same files, the PostScript is 6 times smaller for photos (2.4 MB against 15.5 MB) and up to 8 times faster (0.02 s against 0.17 s on a LibreOffice page). Pages with transparency are drawn as a picture when the caller can render one, else opaque with a note. 300 mutated PDFs in the tests are each converted or refused in words.
- **New: PostScript and EPS to SVG** (`bookport.ps.to_svg`), for figures in books, which can't hold a PDF. Text is drawn as glyph outlines from the fonts in the file (Type 1 with flex and accented glyphs, CFF, TrueType, Type 3), so it looks right without them; the standard fonts become SVG text in a similar family, each letter within 0.001 pt of where PostScript put it. Clips, gradients for axial and radial shadings (pictures for the other kinds), patterns, and pictures as PNG (JPEGs as they are). Drawn next to the same program's PDF, the worst quarter of each page scores an SSIM of 0.988 to 1.0 (PyMuPDF: paths, strokes, pictures, each kind of font) and 0.977 to 0.997 (Edge: clips, shadings, meshes, patterns, enlarged pictures). Adobe's Symbol font, every glyph: 0.988 in Edge. Gradients and patterns carry a plain colour for readers without them, so MuPDF-based readers draw a shading in its average colour instead of black (SSIM 0.74 to 0.98 on a radial shading). CMYK colours use PostScript's simple conversion, with no colour profile.
- **LaTeX: EPS and PostScript figures go into the book** as SVG, so EPUB, HTML and the other formats show them; before, their place and caption were kept and the picture was lost.
- **Fixed:** LaTeX's `\epsfig{file=...}` and `\psfig` never found their picture.
- **PostScript and EPS are read as books** by `bookport.read` (through a PDF of their pages), so they convert to EPUB and the rest; 0.3.0 read the program itself as plain text. `bookport.convert` (given no writer options) and the command line (given no `--page-size`, `--text-size` or `--epub-version`) send them to `.pdf` through `ps.to_pdf`, every page as drawn.
- PostScript, as the reference has it: `restore` undoes the definitions made since its `save` (an EPS figure that redefines `showpage` no longer merges the pages after it: 2 pages where it gave 1); every bitmap glyph of a Type 3 font draws its own picture (dvips PK fonts all drew the last one); text in a font with a translated matrix (`makefont` for raised text) is placed where it was shown; an uncoloured pattern takes its colour from the stack; the colourant `None` paints nothing; `currentfile` inside a running string reads the file; masked pictures keep their indexes and `Decode`; Type 42 `Metrics` widths reach the PDF; `readline` says false at the end of a file; `rand` gives the same file the same output every time.
- PostScript programs that never ended or filled memory now stop at once: a name defined as itself, `cvrs` with radix 1, arcs of 1e30 degrees, `count copy` and `dup` loops past the stack limit (30 doublings: 8 GB), huge user object numbers, image strings repeated to gigabytes, and, in PDF to PostScript and SVG, hostile font maps, self-referencing TrueType glyphs and shadings of huge triangles. A procedure that ends by calling another reuses its frame: the slowest damaged program in the fuzz tests takes 2.6 s instead of 9.9 s (with memory tracing on), and plain interpreter loops are about 5% faster.
- **Faster:** hex data (`readhexstring`, hex pictures) is read about 50 times faster (9.8 MB: 0.45 s, now 0.009 s), and Separation and DeviceN pictures are converted 4.6 to 11 times faster.
- A PDF taken to PostScript and back by bookport alone keeps every word (Ghostscript's own round trip lost half and all of them on two of the four test files) and draws the same: SSIM 0.995 or more on every page, the 60-page document pixel for pixel.
- **New: rewriting PDFs** (`bookport.pdf.rewrite`): pages kept, put in another order and turned; several PDFs joined; a PDF split into parts; PDFs made smaller. The page objects are copied, not drawn again, so text stays text. Bookmarks follow their pages: on an 85-page book with four chapters, keeping 49 pages in a new order kept the three chapters still there, each pointing at its page's new place, and the title. Splitting it into parts of 20 pages gave each part the chapters of its own pages, and only the objects its pages use.
- **New: smaller PDFs** (`rewrite.compress`). On a 4-page scan at 300 dpi (3.11 MB), pictures at 200 dpi and JPEG quality 85 made 1.27 MB (41%), at 150 dpi and 70 made 0.67 MB (22%); drawn at 150 dpi, the worst page kept a PSNR of 35.7 and 34.5 dB. A text-only 85-page book went from 43.6 KB to 30.0 KB through compressed object streams. Soft masks stay lossless, CMYK and other unusual pictures are left as they are, and a picture that wouldn't shrink by 5% isn't touched.
- **New: an invisible text layer on rewritten pages** (`rewrite.edit(..., text=...)`), for OCR: words laid over a page in render mode 3, each on its own box, on the page as it shows (pages stored turned and cropped included); the page's own drawing kept whole between q and Q. Checked with PyMuPDF: every letter found (ł, ó, ź too) and each word within 2 points across. It's the same layer DjVu's hidden text gets, now in `bookport.pdf.textlayer`; DjVu to PDF writes byte for byte what it did (but the date).
- **New: compact PDF writing**: `Writer.finish(..., compact=True)` packs every object that isn't a stream into compressed object streams with a cross-reference stream (PDF 1.5 readers and later).
- Damaged PDFs through the rewrite are refused in words, never a crash: 390 mutated PDFs, 215 rewritten and 175 refused, none over 10 s.
- **Bigger:** installed, bookport takes 3.9 MB instead of 2.8 MB: the PostScript code, and Adobe's metrics for the 14 standard fonts (0.6 MB).
- Rewriting PDFs: links and bookmarks that jump to a place by name now jump to the page itself, so joined files no longer send a link into the first file (LaTeX names its places the same in every file). Page labels (i, ii, 1, 2...) follow their pages, and the tag tree for screen readers is kept when every page is kept in order. A page taken out on its own (split, or some pages kept) takes only the pictures and fonts it draws: before, every part carried every picture of a file whose pages share one resource dictionary. Bookmarks to web pages stay, open bookmarks stay open, one picture too big to shrink is left as it is instead of stopping the whole file, and anything else a damaged file breaks is refused in words.
- **Fixed: two-column PDF pages read across the gap**, a line of each column in turn. Each column is now read in turn, between the lines that span both (a title, a wide caption).
- **Fixed:** pictures drawn inline in a PDF page (`BI ... ID ... EI`) were read as page instructions: on 18 of 40 test pages the text came out in the wrong order. They're skipped now.
- **Fixed:** preformatted text (`<pre>`, code) lost its indentation in PDFs, and runs of spaces were drawn as one space while the line was measured with all of them. Both are drawn as written now.
- **Fixed:** a book of pictures only, or of bold text only, wrote PDF pages that used a font the page didn't list (the page numbers' font). Strict readers drop such text.
- **Fixed:** square and circle list markers (▪, ◦) were drawn as empty boxes in PDFs: the body font has neither. They're drawn from a font that has them.
- **Fixed:** a picture as tall as a page started a blank page in PDFs, and a table row going on to the next page could draw its first line under the bottom margin.
- **Fixed:** a PDF whose cross-reference table points every object a few bytes off (a hand-edited file) couldn't be read; each object is now found where it really is. Odd `/DecodeParms` (`[null]`, a number) no longer drop a page's text, and one damaged picture is left out instead of failing the whole book.
- **Fixed:** encrypted PDFs with AES-128 and no `/Length` (allowed for that kind) were refused as needing a password.
- **Faster:** decrypting AES-encrypted PDFs is about 25 times faster (256 KB: 4.9 s, now 0.2 s; opening an AES-256 PDF: 2.7 s of key checks, now 0.3 s). Pictures with PNG predictors (most Flate pictures in PDFs) are undone 20 to 40 times faster with Pillow installed (1000 x 1000 colour: 1.37 s, now 0.035 s) and up to 13 times faster without it.
- **Safer:** a few KB of ToUnicode map or font widths could expand into tens of millions of entries (the test file, 300 map ranges and 900 width ranges: about 30 s, now 0.03 s); ranges are now looked up where they are. RunLength data is held to the same size limits as Flate and LZW, and a page over the drawing-operator limit keeps what comes before it instead of losing all its text.
- **Read:** web links on PDF pages now come through as links around their words; scanned pages stored as CCITT Group 4 keep their picture (they were dropped); and text in fonts with no ToUnicode map is read through the embedded font's own character map, instead of glyph numbers shown as letters (when the font can't tell, nothing is shown rather than wrong letters).
- **Faster DjVu:** `bookport.djvu.render` turns pages 25 to 40 times faster (a 2000 x 2000 black-and-white page: 1.0 s, now 0.04 s) and scales them 3 to 5 times faster; finding pages in a bundle no longer searches every component for each page (10,000 pages: 1.0 s, now 0.006 s).
- **Fixed (DjVu):** one damaged page made the whole DjVu to PDF fail; it's left blank with a note now. Text read on several threads (with bookport-native) ran without the size limits. bookport-native: a shape starting left of the page panicked in a debug build.
- **Safer:** four small hostile ebooks could use far more memory or time than their size. A MOBI with HUFF/CDIC text unpacked past the limits (200 one-byte records: 392 MB, now refused at 4 MB); a TCR file did the same (200 KB: 244 MB, now refused); a damaged MOBI index entry added zeros for ever (2,000 entries: 49 s, now 0.3 s); and an LRF page linking one text block 3,000 times gave 3,000 copies (98 MB, now 3 MB and one copy).
- **Fixed:** writing HTMLZ hung for ever when three pictures had clashing names in different folders.
- **Fixed:** writing FB2 changed the book it was given: a GIF or BMP in it became the PNG made for the FB2 file.
- **Fixed:** DOCX, ODT and RTF round trips gave each subject twice; DOCX and ODT replaced the book's date with the day of writing and dropped the publisher, ISBN and series (they go into the document's custom properties now); ODT read two authors as one.
- **Fixed:** a MOBI or AZW3 written by bookport read its own id back as a "source" and as the ASIN; EPUB 3 output kept identifier schemes other than ISBN, UUID and URL only as bare values, so an ASIN came back as an unnamed id.
- **Fixed:** PalmDOC and zTXT output turned every letter outside Western European into "?" ("Война и мир" came back as "????? ? ???"); such books are written as UTF-8 now.
- **Fixed:** LIT books whose pages share a name in different folders sent links and the contents to the wrong page; a damaged section number was reported as DRM; one stray byte in a page lost the whole book; odd table numbers (`colspan="²"`, a huge `rowspan`) failed the write.
- **Fixed:** CHM pictures and styles named in another case than the file were lost, and every CHM was read as Western European: Russian, Greek, Turkish, Japanese, Chinese and the other Windows code pages are now taken from the file's language.
- **Fixed:** an emoji in PML (`\UD83D\UDE00`) made the whole book fail, PML output wrote emoji as "?", and footnotes and sidebars lost their character codes ("caf\a233" became "caf233").
- **Fixed:** `bookport --info` failed on titles such as "Война и мир" when its output went to a pipe or a file on Windows; it writes UTF-8 there now. With an output file too, `--info` now also converts.
- **Fixed:** errors inside a writer (an LRF description too long for its 16-bit size, an EPUB `version="3"` given as text) came out as Python errors instead of a `BookportError`. Long LRF descriptions are shortened to fit, and EPUB versions other than 2 and 3 are refused by name.
- **Fixed:** an EPUB title with `display-seq` "1.0" made the whole book unreadable; a MOBI's `<head>` leftovers (a `<link>`, stray text) ended up in chapter one, and `<header>` was taken for `<head>`; Rocket eBook links between pages broke, and a line break in a title wrote a key of its own; FB2 sections without ids got different ids on every read; RAR 5 comics with a password on the pages only said "no pages" instead of naming the password.
- **Faster:** writing LIT with many ids (16,000: 29 s, now 0.2 s); MOBI tables of contents (10,000 entries: 1.8 s, now 0.1 s); PNG pictures are unfiltered by Pillow when it's installed (Paeth, 800 x 600: 0.31 s, now 0.01 s) and up to 15 times faster without it; telling a KF8-only `.mobi` from a joint one reads its header instead of the whole file; DOCX converts a picture used many times once.
- **Less memory:** EPUB, HTMLZ and TXTZ are written straight to the file instead of being built in memory first (a book with 40 MB of pictures: 46 to 51 MB more at the peak, now 4 to 12 MB).
- **Safer markup files:** small hostile files no longer run for minutes or fill memory, each stops where a limit is reached, keeps what came before and says so in `Book.lost`. A LaTeX environment whose end code ends itself (60 bytes) and a macro that doubles its argument (29 bytes) ran for ever, now 0.4 s and 0.9 s; rST substitutions that use each other (546 bytes) ran past 20 s, now 1.1 s; roff strings made of strings (290 bytes) made 10 MB of text, now 64 KB; an AsciiDoc table cell `1000*.500+|x` filled thousands of rows; a LaTeX column spec `*{100}{*{100}{...}}` asked for 100 million columns; Org macros, AsciiDoc attributes, BibTeX `@string`s and Typst's `#lorem` grew without a limit; and includes that each include the next file several times are held to 500 files in all (rST, Org, AsciiDoc).

- **Fixed (EPUB and the other formats that clean pages):** text after a `<style>` in the body moved to the start of its paragraph; links to an id renamed on a later page (Python-Markdown's `fn:1`, ids starting with a digit) lost their place on that page; a link to a repeated id went to the repeat instead of the first; `colspan="1e999"` stopped the EPUB.
- **Fixed (Markdown):** `[text][ref]` links in a long file's earlier chapters stayed as text when the definitions came at the end; two-space line breaks were lost when reading and when writing; spaces at the edges of emphasis were lost (`word<em> italic</em>` became `word*italic*`); a link target in front of a list or code block turned the first item into text and kept the fence from opening.

Written LaTeX turned `a---b` into an en dash and backticks into quotes, showed `\url` text with its escapes, wrote ordinary `<div>`s of HTML and EPUB books as theorems (`\newtheorem{calibre}{Hope}`) and numbered unnumbered ones.

Asciidoctor's literal monospace, `` `+text+` ``, is read.

## 2026-11-05: bookport 0.3.0, markup languages, equations, citations, DjVu and ODT writing

- **New: markup languages.** bookport reads and writes LaTeX, reStructuredText (Sphinx documentation too), Org, AsciiDoc (Asciidoctor), MediaWiki, Typst, DocBook (reads 4 and 5, writes 5), man pages and Textile, and so converts each of them to and from every other format it knows. Measured against Pandoc 3.12 on real documents (structure counted the same way on both sides, `benchmarks/compare_pandoc.py`), bookport was faster on every file but three LaTeX ones where Pandoc finds almost nothing:
  - **LaTeX:** median 0.100 s instead of 0.271 s on 11 arXiv papers; three papers Pandoc didn't finish in a minute take 0.08 to 0.27 s, and two it can't read at all (ResNet, a plain-TeX paper) are read. Sections, lists, tables (`\multicolumn`, `\multirow`, longtable), figures, footnotes, theorems, the document's own macros, `\input`/`\include` from its folder, and cross-references with the numbers LaTeX gives them. Written LaTeX is a complete document with the packages it needs.
  - **reStructuredText:** Python's documentation (347 files) in 5.4 s instead of 329.5 s, with Sphinx's roles resolved into links (3,102 links where Pandoc found 832).
  - **Org:** the 900 KB Org manual in 0.77 s instead of 4.42 s, internal links followed as Org does.
  - **AsciiDoc:** the whole Pro Git book with its includes in 0.76 s (Pandoc stops at a missing include); attributes, conditionals and `include::` with `lines`/`tag`/`leveloffset`.
  - **MediaWiki:** Wikipedia articles in a median 0.023 s instead of 0.54 s; five articles Pandoc can't read are read, and on others Pandoc silently drops whole sections (Pythagorean theorem: 2,039 words against 7,811). Templates are left out and counted.
  - **man pages:** a median 0.0045 s instead of 0.066 s, the same headings, paragraphs, tables and cells as Pandoc on 171 pages, and the 310 alias pages (`.so`) that Pandoc reads as empty. Files named like `ls.1` are recognised.
  - **DocBook, Textile, Typst:** 0.0015 s, 0.0045 s and 0.0035 s median instead of 0.076 s, 0.16 s and 0.108 s.
  - Anything a reader can't turn into structure is kept as text, and what was left out is listed in `book.lost`.
- **New: DjVu.** bookport reads DjVu books (bundled and indirect, black-and-white, greyscale and colour pages, the OCR text layer, outlines and links) and turns them into PDF and text with `bookport.djvu.to_pdf` and `to_text`, or into any other format through `bookport.read`. Measured against DjVuLibre 3.5 on 20 public-domain books (3,149 pages):
  - **PDF:** 28.9 s instead of 388.8 s for all 20 (5.2 to 16.8 times faster on every book), 146 MB instead of 2,194 MB (2.6 to 28 times smaller on every book), and searchable: 829,314 words a PDF reader can find, where DjVuLibre's PDFs have none. Black-and-white layers go in as JBIG2 or CCITT G4, backgrounds as JPEG, outlines as bookmarks.
  - **Text:** 0.71 s instead of 4.5 s through ConvertAll, the same text as djvutxt on 19 of 20 books (on the 20th, words DjVuLibre skips are kept).
  - **Pages** render the same as DjVuLibre's: on 59 sample pages, 53 are pixel for pixel identical and the rest above 52 dB. Drawn from the PDF, pages come within 48.4 dB (median; worst page 30.6 dB) of DjVuLibre's rendering, against 36.5 dB (worst page 0.1 dB) for DjVuLibre's own PDFs, which are 12 times bigger.
  - These times are with the new, optional bookport-native package (compiled decoders). Without it bookport reads DjVu in pure Python with the same results: text is still faster than djvutxt, but PDFs take about 13 times as long as DjVuLibre's (median of 3 pages from each book).
- **New: equations.** TeX, Typst, MathML and Word's Office Math convert into each other, in Markdown (`$...$`, following Pandoc's rules, so "$5 and $10" stays text), HTML, EPUB, DOCX and ODT. All 2,436 distinct formulas in the arXiv test papers convert without an error and come back the same through TeX, Office Math and Typst; on the 240 of a 300-formula sample Pandoc could read, 239 have the same structure as Pandoc's MathML.
- **New: citations.** BibTeX and BibLaTeX bibliographies are read (or the `.bbl` arXiv ships), and `\cite`, `[@key]` and Org's `[cite:@key]` become citations with a reference list, author-year or numbered. On two arXiv papers: 104 of Pandoc's 104 citations, and 73 where Pandoc found 72 (it drops the table holding the 73rd).
- **New: writes ODT** (OpenDocument text): headings, lists, tables with merged cells, pictures, footnotes, links, and equations LibreOffice can edit.
- **Better Word documents:** real bulleted and numbered lists (nesting, start numbers), real footnotes, code in Word styles Pandoc and Word know, table header rows, merged cells, captions and definition lists. On 15 test documents, the list items Pandoc found missing went from 362 to 19, footnotes from 28 to 0, tables from 12 to 0; LibreOffice opens and re-saves them with the same structure (13 of 13).
- **Markdown** reads Pandoc's footnotes, definition lists, simple, multiline and grid tables with captions, fenced divs, pictures alone in a paragraph as figures, H~2~O / x^2^, numbered lists in every style (a. A) iv. (2) #.), line blocks, `{#id .class}` attributes on headings, spans and code, and raw TeX and HTML passages, and turns straight quotes, `--`, `---` and `...` into typographic ones as Pandoc does; footnotes are written as `[^1]`. On the 21 Markdown test files, bookport reads the same links (29 of 29) and the same headings, tables, cells, pictures, notes and equations as Pandoc, in a median 0.4 ms instead of 0.07 s. HTML made by Pandoc, Python-Markdown and most site generators keeps its footnotes as real notes. ODT reading keeps equations, merged cells, list start numbers and multi-line code.
- **Fixed:** Word documents with text boxes lost their text (only the box's picture was kept). Their text is read now, in page order: a PDF that LibreOffice turned into a DOCX (each line a text box) keeps all of it.
- **Fixed:** a stray `<col>` inside a table row ended in a ValueError instead of a book.
- **Fixed:** loose lists (items with paragraphs) lost their bullets and numbers in TXT, RTF, PDF and the other formats laid out from text.
- Text formats can save the pictures they refer to beside themselves (`write(..., pictures=True)`).
- Hostile documents are contained: includes only from the document's folder or one level up, include loops and macro bombs stopped, very deep nesting refused; each reader has tests for these.
- **Fixed:** on Linux and macOS, a link written with Windows backslashes (`pics\x.png`, `..\..\x.png`) was taken as one odd file name inside the book's folder, so a book made on Windows lost those pictures there (never a file from outside the folder), and a 0.2.0 test failed on Linux. Backslashes now separate folders everywhere, as they always did on Windows.
- **Tests:** CI runs on Linux as well as Windows (new in 0.2.0); the suite now passes there.

## 2026-11-01: bookport 0.2.0, faster CHM, unpacking CHM and LIT, CBZ writing, kerned PDFs

- **Fixed:** EPUBs made from Python's documentation CHM had 329 epubcheck errors; now 0. Tables with `<col>` straight in the table (as Sphinx writes them) had the columns wrapped in rows and cells, rows were mixed with row groups, and a web link with a bare "%" was left invalid. The columns now go in a `<colgroup>`, loose rows in a `<tbody>`, and the "%" is escaped.
- **New:** PDF text is kerned: letter pairs such as AV, To and r. are spaced as the font's own kerning table says (checked against fontTools for all 8,836 pairs of printable ASCII characters in each of the four Noto Serif styles). Lines fit a few more words (144,249 lines instead of 144,383 over the 11 corpus books), and typesetting takes 1.3% longer.
- **Fixed:** in a PDF, a table column exactly as wide as its longest word could break that word between letters ("PAG" and "E") because of a rounding error.
- **Fixed:** code blocks in CHM help files kept Windows line breaks when converted, so a text file had them mixed with Unix ones (42,369 of them in Python's documentation). Pages are read with one kind of line break now, as XML readers do.
- **More metadata kept** in the rarer formats: RB keeps the publisher, copyright and ISBN (its info page has keys for them); SNB and LRF keep the date they already wrote, which reading now picks up; LRF keeps every subject, not just the first.
- **New:** Plucker books keep their pictures: Palm OS bitmaps (1 to 16 bits a pixel, colour tables, transparency, scan-line, RLE and PackBits compression, bitmaps of several depths) become PNG, and composite images are joined into one. Until now they were left out.
- **New:** writes CBZ comics from books made of pictures (comics read from CBZ, CBR or a folder, fixed-layout picture books): the pages in reading order, a ComicInfo.xml with the metadata and the chapters as page bookmarks, and the same metadata in the ZIP comment for calibre's library. Books with pages of text are refused with a clear message.
- **New:** `bookport.unpack(path)` gives the files inside a CHM or LIT container, for extracting them. On Python's documentation CHM it gives the same 555 files as 7-Zip, all 46,823,729 bytes identical. DRM-protected LIT is refused, as when converting.
- Comics read from a CBZ take their chapters from ComicInfo.xml page bookmarks when it has them.
- **Faster:** CHM and LIT decompression (LZX) is 4.7 times faster: Python's documentation CHM decodes in 3.98 s instead of 18.68 s, and becomes an EPUB in 19.5 s instead of 27.1 s (best of 3 in one process; the side-by-side table in the README times a fresh process per conversion: 18.0 s). The output is byte-identical.
- **Fixed:** reading a PDF dropped a line at the top or bottom of pages when its words had digits inside them ("A320", "1880s", "word58"): such lines looked like a running header once their numbers were masked. A 144,227-word book read back as 137,927 words; now all 144,227. Only whole numbers are masked now, so page numbers and headers like "Chapter 12" are still dropped.
- **Fixed:** in a PDF bookport wrote, characters that no font had (drawn as empty boxes) all copied and searched as the first such character, so "∀x ∃y" read back as "←x ←y". They now read back as U+FFFD, the standard sign for an unknown character.
- The `BOOKPORT_FALLBACK_FONTS` environment variable (TrueType fonts tried first for characters the bundled fonts lack, such as CJK on Linux) is now documented in the README, and tested.
- **Smaller:** the bundled fonts take 0.86 MB instead of 2.4 MB: they're stored xz-compressed, without two tables bookport doesn't read (GSUB, and the glyph names in post; `tools/slim_fonts.py` makes them from Noto's release). The PDFs bookport writes are byte for byte the same (9 of 9 sample PDFs, every page size and text size); loading all five fonts takes 59 ms instead of 12 ms. The package is 1.7 MB instead of 3.2 MB.
- **Fixed:** on Python 3.10 and 3.11, a damaged ZIP-based book (EPUB, HTMLZ, DOCX and the rest) whose member claims more bytes than the file holds made reading set aside that much memory first: a 3 KB file asked for 257 MB. Such a member is now refused at once as damaged (under 20 MB peak). Python 3.12 and later already caught it.

## 2026-10-30: bookport 0.1.0

First release: bookport 0.1.0.

- **Reads and writes** EPUB 2 and 3, Kindle MOBI (joint MOBI 6 + KF8), AZW, AZW3, FictionBook 2 (and `.fb2.zip`), HTML, HTMLZ, plain text, TXTZ, Markdown, Word (DOCX), RTF, PDF, Palm database ebooks (eReader, PalmDOC, zTXT), PML and PMLZ, Psion TCR, Rocket eBook (RB), Shanda Bambook (SNB), Sony LRF and Microsoft Reader (LIT, without DRM).
- **Reads** OpenDocument text (ODT), Compiled HTML Help (CHM), Plucker, KF8 and MOBI files made by any tool (including HUFF/CDIC-compressed ones), comics (CBZ, CBR with stored pages, a folder of images, a single image) and PDFs made by any tool.
- **Refuses DRM.** Protected EPUB (Adobe, Readium LCP, Apple), Kindle, eReader, LIT, PDF (password needed) and encrypted comic archives raise `DRMError`. bookport never removes DRM.
- **EPUBs pass epubcheck** with zero errors: documents from any source are cleaned into valid XHTML5 first.
- **Its own PDF typesetter**: justified text, headings kept with the text after them, lists, tables that split across pages, images, links, a bookmark outline from the TOC, page numbers and embedded Noto font subsets, so the text can be searched and copied. Page size (phone, 6-inch e-reader, A5, A4, Letter) and text size (small, normal, large) are options.
- **Its own PDF reader**: cross-reference streams, object streams, damaged-file repair, RC4 and AES encryption with an empty password, ToUnicode text extraction reflowed into paragraphs and headings, end-of-line hyphens resolved from the book's own vocabulary, running headers and page numbers dropped, images and the outline kept.
- **Command line**: `bookport SOURCE OUTPUT`, `bookport --info BOOK`, `bookport --formats`; `--to` and `--epub-version`, and `--page-size` and `--text-size` checked before the book is read. Errors print a one-line message, never a traceback.
- **Safe with books from anywhere**: local pictures, styles, covers and pages are read only from the book's folder and one level up (never absolute, network or `file:` paths); unpacking is limited to 512 MB per part and 2 GB per book, pictures to 100 million pixels, nesting to 128 levels (a page nested 100,000 elements deep still becomes an EPUB in about 3 s), tables of contents to 32 levels; XML entity declarations are refused; damaged files of any kind raise `BookportError` and nothing else. Checked by a file built for each limit (55 of them failed before the fix) and by fuzzing 25 formats (1,250 mutants, none escape; 27 of 350 escaped before).
- **Options are checked**: an option a format doesn't take raises `BookportError` naming the ones it does.
- **Against Calibre 9.17** on the same books (median per conversion): EPUB to PDF in 1.40 s and 40 MB against 8.91 s and 1,138 MB; EPUB to MOBI in 0.96 s against 1.60 s; Kindle to EPUB with 0 epubcheck errors against 7,212; Python's documentation CHM in 20.5 s against 381.8 s. Words, TOC titles, images, metadata and covers kept are equal or better on every output format. Install size 3.0 MB against 666.5 MB.
- Pure Python with no dependencies; Pillow, when installed, widens the image formats that can be converted (WebP, TIFF).
